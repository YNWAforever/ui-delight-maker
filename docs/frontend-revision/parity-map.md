# Route / Function Parity Map

Step A3. One row per authenticated route: what it loads, through which keys, from which server functions, what it can mutate, and what actually works today.

**35 rows, not the plan's 31** — see PROGRESS.md PC-1. The four routes the plan omitted are `/account`, `/notifications`, `/clients/import` and `/admin/`, and the PDF route's real id is `/quotes/$id_/pdf`.

This map is the contract that no real function is lost. The "Before" column is filled here from a static read of every route and every server function it calls; the "After" column is filled during Phases C–E as each route is revised, and F3 walks the REAL actions to confirm them.

**A caveat that belongs on the front page:** "Before" describes what the code *would* do against a working backend. No runtime verification was possible in this environment (see validation-report.md EG-2), so nothing here rests on having watched the action succeed in a browser.

Two in-repo registries also enumerate routes and disagree with this map and with each other: `src/lib/performance/route-performance.ts` (34 paths) and `src/server/db/route-loader-contract.ts` (34 entries). Both spell the PDF route without the underscore. Any route work must update them, because tests enforce them.

**Slice-specific answer — `quotes.account_id` is canonical, not a name match.** `quotes.account_id uuid references accounts(id) on delete set null` is added in `neon/migrations/003_client_relationship_360.sql:105`, given a named FK constraint at :143-152, re-asserted in `004_clientops_schema_hardening.sql:13` and indexed at `004:33`. Every consumer joins on that column and **nothing anywhere matches quotes to accounts by company name** — `src/server/repositories/company-workspace.ts:27` (`select count(*)::int from quotes where account_id = $1`), `:45-46` (quote totals by currency), `src/server/repositories/account-timeline.ts:75` (`select * from quotes where account_id = $1`), `src/server/auth/resource-ownership.ts:45` (`left join accounts a on a.id = q.account_id`). It is also read/written end-to-end: `account_id` is in `QUOTE_COLUMNS` (repositories/quotes.ts:433), in `editableQuoteUpdateColumns` (:63), a filter on both list paths (:114, :137), and an insert column (:244, value `input.account_id ?? null` at :254). **The link is real and the write path exists; the UI simply never uses it.** `quotes.new.tsx`'s payload (:240-255) sets `lead_id` and `client_id` only, so every quote created through the product persists `account_id = NULL` and is invisible to Account 360, and `quotes.$id.tsx` never renders or offers to set it. Only `scripts/clientops/seed-smoke-data.ts:1029` and `:1141` populate it. C4/D2 should therefore **derive and backfill `account_id`, not build name matching** — the canonical column is already there, indexed, and queried.

**VF-3 check for this slice — no invalidation bug found.** `quotes.new` and `quotes.$id_/pdf` bypass the cache but perform no mutation that must refresh them (`quotes.new` navigates away). `quotes.$id` bypasses the cache in its loader but re-reads through `useQuery` on `crmQueryKeys.quotes.detail(id)` (:150-155), so the `invalidateQueries` calls in `invalidateQuoteMutation` do land. `/quotes` is a genuine `ensureQueryData` route and `src/router.tsx:19-25` sets no `defaultStaleTime`, so its loader re-runs on navigation and picks up the invalidated entry. None of the four routes needs `router.invalidate({filter})` today.
