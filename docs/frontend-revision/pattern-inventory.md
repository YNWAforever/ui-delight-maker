# Shared Pattern Inventory

Step A5. What each route uses today for header, metrics, filters, list, empty, loading, error, status, detail panel and action placement — and the decision for each Instruction §10 component.

## The headline finding

The product has **two rival header components with zero overlap** and ten routes using neither:

| Component | Routes |
|---|---|
| `PageHeader` (`src/components/page-header.tsx`) | 15 |
| `CommandHeader` (`src/components/sales/command-header.tsx`) | 10 |
| neither | 10 — `/account`, the eight `/admin/*` routes, `/quotes/$id_/pdf` |

That split is the concrete, mechanical cause of the "pages feel like unrelated templates" problem in Instruction §3.6. Converging it is the single highest-leverage change in Phase B.

`CommandHeader` is the better ancestor: its `status` prop already renders an uppercase eyebrow above the title, which is exactly §8.3's *context label*. `PageHeader` has no equivalent. Neither supports `backHref`, neither separates a primary action from secondary actions (both take one opaque `actions` node), and **both cap the page title at `text-xl` (20px)** where §7.3 asks for 24–30px. Note the naming collision to avoid in B3: `CommandHeader.status` means "context", while §8.3's *status* is a separate freshness indicator.

## Instruction §10 component decisions

Per PROGRESS.md PC-5, shared components live in **`src/components/sales/`** behind its existing barrel — the only barrel in the tree — not in a new `workspace/` folder.

| §10 component | Decision | Basis |
|---|---|---|
| `WorkspaceHeader` | **converge** `PageHeader` + `CommandHeader` | both exist, 15/10 split, zero overlap |
| `MetricStrip` | **extend** | already exists in the barrel with a `SalesMetric` type (PC-6) |
| `EmptyWorkspaceState` | **extend** | `empty-state.tsx` and `sales/work-surface-empty.tsx` both exist |
| `RecordSummaryPanel` | **promote** | `sales/context-panel.tsx` is the page-local ancestor |
| `LifecycleBadge`, `AiRunStatus` | **extend** `status-badge.tsx` | `STATUS_STYLES` already holds 30 keys across 6 domains (PC-10) |
| `DataTableShell`, `ResponsiveRecordList`, `AttentionQueue`, `FilterToolbar`, `ActivityTimeline`, `StickyActionBar`, `OwnerDisplay`, `RelationshipHealthDisplay`, `EvidenceList`, `LoadingSkeleton`, `FilteredEmptyState`, `ErrorState` | **create** | no equivalent found |

## Global styling facts that change Phase B

From `src/styles.css` (179 lines, OKLCH tokens, 39 light / 38 dark):

- `table { font-variant-numeric: tabular-nums; }` is **already global** — §7.3's tabular-numerals requirement is met for tables; only non-table KPI values need the utility.
- `prefers-reduced-motion` is **already handled** globally — §14 satisfied.
- Semantic roles `success`, `warning`, `info`, `destructive` all exist with foregrounds, plus a full separate `sidebar-*` token set and `chart-1..5` mapped semantically.
- **Gap:** §7.2 asks for a "dark or strongly differentiated navigation rail". In dark mode `--sidebar` is `oklch(0.18 …)` against `--background` `oklch(0.15 …)` — differentiated. In **light mode it is `oklch(0.98 …)` against `oklch(0.985 …)`, a 0.005 lightness difference, i.e. invisible.** A6 must address this.
- **Gap:** no attention-tint token exists for exception queues (§7.2, last role).
- **Hazard:** `body { overflow-x: hidden }`. This *masks* horizontal overflow rather than preventing it, so §19's "no global horizontal overflow at 375px" can appear satisfied while content is silently clipped and unreachable. F1 must measure `documentElement.scrollWidth` and also check for clipped content, not just the absence of a scrollbar.
