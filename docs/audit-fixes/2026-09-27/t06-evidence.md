- Migration 011 freezes all listed commercial columns after a quote leaves draft/revised, including a same-statement transition. It protects normalized quote_line_items against insert/update/delete and quote_versions against update/delete. Existing rows are not rewritten or reclassified. The schema readiness contract now checks these triggers and T05 approval/receipt objects. The migration was applied only to a fresh, dedicated local PostgreSQL database.
- The server edit endpoint routes through updateQuoteCommercial. It locks the current quote row, reloads current actor role/status and permission overrides, checks row scope, and permits only draft/revised commercial edits. A direct repository/SQL writer is still caught by the database trigger.
- createQuoteRevision derives a separate editable quote from the immutable issued/accepted base snapshot. The old quote and its issued version remain unchanged. The parent gets a version B reference with its own valid parent snapshot identity and a revision_quote_id pointer to the new draft. A scoped command receipt makes retries return the same child. The quote UI offers Create revision for sent/viewed/accepted and ignores a stale edit URL for locked statuses; review links no longer imply that pending commercial fields are editable.
- The read-only inspectQuoteIntegrity report pages through sent/viewed/accepted quotes and returns IDs plus issue codes for missing/wrong version, wrong accepted/issued reason, malformed snapshot, unverifiable/drifted identity, and commercial drift. It performs no repair or customer-data export. Historical mismatches remain blocked for manual review.
