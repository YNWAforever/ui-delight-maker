# T09 currency, acceptance period, and Hong Kong date evidence

Scope: CO-10 and CO-26. Code commit `8152e55` on `codex/clientops-currency-date`; [draft PR #87](https://github.com/YNWAforever/ui-delight-maker/pull/87) is stacked on T08 draft PR #86.

- Correct-behavior tests were red before the fix: the formatter used UTC and integer money; the report still had one HKD-only column/chart; the dashboard returned a scalar quote value; the real PostgreSQL report did not return `revenueTotals`; and lead quote summaries dropped their currency. The audit probes remain defect evidence, not release gates.
- The accepted quote report reads `accepted_at` and the matching `quote_versions` acceptance snapshot. It uses Hong Kong half-open day bounds `[start,end)`, groups PostgreSQL `numeric` sums by snapshot currency, and returns decimal strings. A later metadata `updated_at` change does not move an old acceptance into the selected period. Missing date, version, or valid snapshot stays outside measured totals and increments the unverified count; nothing is backfilled from `updated_at`.
- Pipeline and dashboard quote totals are grouped by stored currency. The revenue screen uses a week/currency table and exact values; CSV includes currency and exact decimal text. The label is “Accepted quote value”, distinct from invoices or cash. Lead cards and previews carry the quote currency. No FX rate is inferred.
- `formatDateTime` and other instant formatters use a fixed `Asia/Hong_Kong` zone with `en-GB`; `formatDateOnly` preserves YYYY-MM-DD calendar values. The existing `business-date.ts` was already explicitly Hong Kong based. Tests cover HK 00:30 on the following UTC day, New Year rollover, host-time-zone independence, date-only values, and two-decimal values including a decimal beyond safe JS integer precision.
- Real isolated PostgreSQL tests passed: `revenue-currency.integration.test.ts` 2/2, including HKD 100.25 and USD 100.00 as separate totals, an actual later metadata update to an old accepted quote, a null `accepted_at` unverified record, and the inclusive HK midnight/exclusive preceding second. No mock database or production connection was used for these cases.
- Final complete suite passed 283/283 files and 2,028/2,028 tests on the disposable PostgreSQL container with four workers and a 15-second test allowance. A subsequent stronger metadata-update assertion and New Year formatter assertion passed focused runs (2/2 database and 22/22 formatter/report-route). TypeScript and pure `bunx vite build` passed. Lint had 0 errors and one pre-existing Fast Refresh warning; `git diff --check` passed. An earlier full run exposed outdated UTC/whole-money test expectations and a temporary SQL fixture missing the acceptance columns; these were corrected and the final suite passed.
- No T09 schema migration is required: `accepted_at` and `accepted_version_id` already exist in migration 005. [Read-only reconciliation SQL](t09-reconciliation.sql) completed on the disposable test database. Its accumulated fixtures showed 237 accepted quotes, 192 without `accepted_at`, 185 without `accepted_version_id`, and zero dangling/mismatched/wrong-reason/invalid-money versions. These counts are fixture data, not live ClientOps data.
- Authenticated multi-role browser UAT and live legacy reconciliation remain unavailable. CO-10 and CO-26 remain `in_progress` until those acceptance gates are satisfied. No production data, deployment, customer message, or migration/seed build wrapper was used.
