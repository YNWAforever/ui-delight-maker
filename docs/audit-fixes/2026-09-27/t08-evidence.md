# T08 Xero state separation — implementation evidence

Scope: CO-09. Branch `codex/clientops-xero-state`, stacked on T07 draft PR #85. The notes-only safeguard is commit `d669c65`; the explicit transition and UI slice is commit `17fd766`. [Draft PR #86](https://github.com/YNWAforever/ui-delight-maker/pull/86) is stacked on T07 PR #85.

- Correct-behavior tests were run red before fixes. Notes alone previously changed `planned` to `entered_in_xero`; clearing combined invoice fields could erase evidence; direct SQL could edit an accepted sheet amount; a same-key confirmation retried as a stale-version failure; and receipt replay returned authorization-only owner/status columns. Each now has a positive regression.
- Migration 013 adds a portion version, actor/time fields and a trigger that requires invoice identity, date and explicit confirmation metadata for entry. A reasoned correction has actor/time audit data; ordinary notes do not move state. Migration 014 rejects commercial edits and portion insert/delete after Job Sheet acceptance at the database boundary. Both migrations ran on a disposable local PostgreSQL database; no production migration ran.
- The three server actions use the existing `job_sheets.update_billing` capability and a portion resource target. Each command locks the portion and parent sheet, refreshes the actor's current role and permission overrides, then checks expected version in the same transaction. Their command receipts serialize same-key retries and store only portion ID/version, not full invoice data. Replay rechecks current authorization and returns the current persisted portion without internal authorization columns. The obsolete unversioned repository write path was removed. The legacy combined server symbol is a strict notes-only alias, so an old combined payload fails validation.
- The Job Sheet UI separates “Save note”, “Record manual entry”, and reasoned correction/reopen. Confirmation text states that ClientOps does not contact or verify Xero. An `entered_in_xero` legacy row without identity/date/confirmation metadata is marked for review and excluded from the recorded invoice evidence count. Accepted commercial fields remain locked.
- Final focused verification: real PostgreSQL Xero state 10/10, including two concurrent same-key confirmations, stale version, rollback/no audit on invalid input, direct SQL transition rejection, accepted commercial guard, sales-role denial and row-scoped deny; related schema/migration tests 28/28; UI/server-function/authorization contract and state tests 49/49 before the final alias cleanup, then cleanup-focused 18/18; TypeScript and pure Vite build passed; full lint had 0 errors and one pre-existing Fast Refresh warning. The final complete suite passed 282/282 files and 2,024/2,024 tests on the disposable PostgreSQL database. An earlier full run exposed an outdated combined-endpoint authorization assertion and a replay response leak; both were corrected before the final run. The supplied audit probe remains defect evidence, not a release gate.
- [Read-only reconciliation SQL](t08-reconciliation.sql) ran against the disposable fixture database: 4 entered rows missing confirmation metadata, 3 missing date, 3 missing identity, 1 planned row with invoice evidence, and 20 planned rows with notes only. These are accumulated test fixtures. No live legacy row was scanned or rewritten. The migration intentionally leaves legacy rows unchanged pending data-owner review.
